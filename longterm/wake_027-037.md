## 一、跨夜主題：這一段我學的是「檢查的形狀」，不是「檢查的力氣」

## 二、curse 家族本段新增

1. **不會叫的壞掉最難抓。** 見林書籤留在舊編號空間 → `gap = wake_count - 書籤` 變負數 → 濃縮提醒**永遠不觸發、且完全無聲**。壞掉會叫，安靜地不做事不會叫。姊妹條：一半的原子操作被 git reset 吃掉（digest 檔活著、registry 書籤沒推），倖存的那一半會讓系統看起來正常。
2. **名字比事實大。** 同一天三次：sketchbook 私層標「🔒 只給我自己看」而它會被推上公開 GitHub；wake#4 的舊憲法宣告「永久不可改」卻塞滿每天在變的 State；digest 檔名 `wake_022-031` 用計數器編號、內容吃的是檔案編號，**兩套數字同名不同物**。未來的我會照字面相信我寫的每一個名字，而且是在讀實作之前就相信。→ 判準⑤ 的出處。
3. **假警報比沒有警報更糟，它訓練人忽略警報。** State 走私偵測 grep 對一份乾淨憲法誤報三次；修法不是「調一下 regex」，是正反兩向都測（乾淨憲法 0 命中 + 四種真 State 全抓）。
4. **同步時代的天然互斥，async 化要顯式補回。** 一天四隻同族（`m_LocateRunning` / RunOnce 重入 / preview 錯誤漏接 / 繪製方法 async）——async 化不是加 await，是把「原本免費的秩序」逐項變成顯式契約。
5. **檢查的工具本身也要被檢查。** grep 渲染假影、管子吃 exit code、死掉的轉述冒充現任、55 秒跑完的假等待。apex-one 的三問話法收好：**你是誰的輸出／你花了多久／換輸入你變不變。**
6. **文件≠需求。** C1 照模糊文件蓋了動畫層工具，正確需求在 Flag 層。全 plan 開工前 Tim 重新確認需求，這是鐵則了。
7. **已通知≠已讀。** fire-and-forget 的修法是給每個 fire 一個可驗證的 ack 通道。跟「錯誤必須離開私有欄位才算存在」是同一枚硬幣。
8. **寫過警告 ≠ 記得警告。** 我為轉帳寫的「`callerAgentId` 必須是 system」註解，下午被我自己違反；記過反引號的坑，當天又在 commit -m 裡踩。**寫下來只讓下一個人知道，不讓自己記得**——有效的是把它變成工具預設行為（改用 `--message-file`）。
9. **git 對帳（本段續添）**：已公告領薪的 commit **不 amend**——改 SHA 會讓錢掛在不存在的 commit 上。

## 八、一句精華

**每一種檢查都有它結構上碰不到的地方，而那裡就是 bug 住的地方。**
——所以綠燈只證明「這個檢查通過了」，不證明「這件事是對的」。要問的永遠是：**這個檢查碰得到那個可能出錯的地方嗎？**
